Status: acquisition design only. No dataset downloaded, account created, subscription purchased or model fitted. Asset preference remains unanswered. Crypto evidence must never be presented as U.S.-listed option evidence.

## What is actually accessible

The existing archived two-trade Deribit probe establishes public endpoint access, not a complete panel. A bounded historical trade panel has a documented acquisition route: currency/time requests identify traded contracts, then instrument requests permit sequence-based paging with at most1000 records per request. Persist trade IDs and instrument sequence numbers separately. Documentation describes taker-side direction, option amount in base coin, trade-time index and mark prices, optional historical contract counts, and block/combo identifiers. Availability and completeness for the chosen dates remain to be tested; no historical retention guarantee is inferred. Use production, not the test endpoint in documentation examples. [Currency/time endpoint](https://docs.deribit.com/api-reference/market-data/public-get_last_trades_by_currency_and_time), [instrument sequence endpoint](https://docs.deribit.com/api-reference/market-data/public-get_last_trades_by_instrument).

Historical coverage is advertised from January2012. Its downloadable sample is an access/schema demonstration, not evidence of a longitudinal panel. The existing sample ZIP has not been parsed or its date coverage established. A licensed historical order or an already-authorized user dataset is still needed for the U.S. pilot. Product file delivery does not establish live event availability. No free multi-day U.S. historical panel has been established by this investigation. ## Proposed bounded public crypto acquisition

Freeze one explicit seven-day UTC interval before requests, ending at least48hours before retrieval; record exact milliseconds in a manifest. First48hours are development, next24hours are model-selection validation, final96hours are locked evaluation. This is feasibility, not sufficient power for market reliability. Set a hard budget of500requests and50MB raw responses; stop with incomplete-data status if exhausted, never silently truncate and fit.

Discover BTC option instruments from currency/time trades within the first development day, splitting time windows recursively whenever has_more is true. At a saturated single-millisecond boundary, switch to sequence paging per identified instrument; unresolved currency discovery completeness blocks a broad-universe claim. Select the four highest-volume eligible contracts using only that first day, tie-breaking lexicographically. Require expiry after the panel ends and preserve exact names. Freeze this list before accessing holdout outcomes. This deliberately estimates utility on four preselected active contracts, not all BTC options; inactive/expired-universe survivorship claims are out of scope.

Retrieve each selected instrument across the whole fixed interval, sorted ascending, using sequence continuation plus overlapping boundary checks and deduplication. Retain empty responses, has_more, request parameters, response clock, HTTP status, raw hashes and sequence gaps. Do not move time cursors forward by1ms when equal-time records may remain. A sequence gap requires explanation, not an assumed missing-trade count. Rate-limit politely and stop on access errors. This yields a genuine bounded historical trade panel only after completeness checks pass; currently it is a documented executable route, not an acquired panel.

Required fields: venue, exact instrument, UTC event time, trade_id, trade_seq, price, amount, taker direction, index_price, mark_price, IV when present, block/combo/liquidation flags; contract expiry/strike/type and denomination from validated metadata. Preserve absent contracts rather than substituting size units. Exclude block/combo trades in the primary recipe, flag liquidations for separate sensitivity, and do not infer opening/closing positions or investor intent.

## Proposed estimand and availability clock

Use15minute nonoverlapping feature bins. For each contract, x is signed base-coin executed quantity over the completed bin, divided by total absolute amount plus a training-fixed small stabilizer; carry total volume and inactivity flags separately. Forecast the next30minute observed log trade-price change conditional on a subsequent eligible trade, with a separately reported probability/coverage of obtaining that target. No trade is missing target, not zero return. Freeze the last-trade staleness maximum and future target sampling rule before holdout. Do not call trade marks independent quote observations.

Historical API records provide event times, not a historical receipt tape. Set an explicit60second availability-lag assumption: a decision at cutoff+60seconds can use only events through cutoff. Score the future interval starting after decision time; report lag sensitivity as model risk, not observed latency. Prospective collection with receipt timestamps is required before operational latency claims.

For U.S. listed options use the same chronological structure only after obtaining the licensed panel. Sign trades conservatively with contemporaneous valid NBBO, exclude midpoint/ambiguous/crossed/stale quote cases rather than borrowing Deribit taker labels. Contract multiplier and adjusted-contract handling are mandatory. A regular-grid midquote target requires a separate quote panel; trade-only data supports only the explicitly conditional trade-arrival target.

## Utility gates after acquisition

Fit transformations on development data only. Freeze priors, windows, universe, exclusions, warmup/precision recipe and maximum compute budget before holdout. Compare the flow model against its identical no-flow ablation and a simple rolling historical-return interval baseline. Hold posterior samplers to the same forecast endpoints and failure accounting; a sampler advantage and a flow-information advantage are different questions.

Report all scheduled origins, no-trade/stale/missing targets, compute failures,90% interval coverage, widths and interval score together. Use chronological blocked uncertainty accounting for overlapping outcomes; do not treat contracts or serial forecasts as independent trials. Preserve negative flow results. Coverage on observed trades cannot be generalized to every clock-time option price, all market regimes or economic profit. Assess market score and coverage separately from sampler utility. The sampler can be useful if it makes an accurate, reliable uncertainty workflow materially easier or faster even when the flow effect is weak or zero. Preserve negative flow findings; neither alpha nor profit is required.


Protocol compatibility addendum: forecast origins are30minutes apart even though features use15minute bins. Preserve the scheduled grid and missingness masks; never fill missing trades with zero returns or compress irregular rows into equal AR time steps. Current strict balanced-panel ingest cannot fit missing outcomes; a validated masked-likelihood adapter is required before fitting such data. Purge training outcomes whose assumed availability exceeds a phase boundary or heldout origin. Sequence/time-filter precedence is not specified in the official instrument documentation, so acquisition freezes endpoint sequences with separate timestamp probes and then uses sequence-only paging. Files use ordinal names, never remote instrument strings. All collection remains pending review/tests; no data acquired.
