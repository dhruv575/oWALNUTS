# Retained-only macro-step jitter preflight

Frozen before candidate construction. Work in an isolated source copy. Keep warmup, base adapted step, mass matrix, refinement checks and production files unchanged. For each retained transition use h=h_base*(1+a*(2*u-1)); a is process configuration in [0,1), u a uniform variate from a separately seeded SmallRng using chain seed and absolute transition index. The schedule is independent of position, momentum, acceptance and kernel RNG consumption. It is constant across the complete transition, including reverse checks. Zero amplitude avoids generating a variate. This implements a state-independent mixture of fixed-step kernels; that argument relies on validity of the component kernels and does not prove empirical mixing.

Use a local copy of KernelTuning for the transition; never multiply the stored adapted step. Record the actual step in per-transition diagnostics and keep metadata's base step unchanged. Warmup is deliberately not jittered. This is a research prototype with an environment-based amplitude and no public API or production promotion. Existing resumable cooperative sampling must derive the same multiplier for the same seed/index.

Build with pinned cached dependencies and release compiler. Preflight both diagonal and dense GP fits with 1100 warmup and 100 retained draws, seed 947700001. Compare original runner with candidate omitted/explicit-zero jitter: every output except elapsed seconds must match. Run amplitude .5 twice and require exact repeatability; check each reported retained step lies in [.5,1.5] times its chain base step and is not constant, zero-jitter steps equal base, all calls reconcile. This is implementation verification, not performance or posterior qualification. Bounded builds 300 seconds/4 GiB, sampling 180 seconds/2 GiB/64 MiB. Preserve failures. Only after this passes freeze fresh statistical calibration and validation; no tuning to the exposed GP tail failure.

Prior art: Stan Reference Manual step-size jitter, https://mc-stan.org/docs/2_36/reference-manual/mcmc.html. It describes possible curvature benefits and extra work or rejections; no guaranteed benefit or novelty is assumed.
