# Sampler allocation audit

Frozen 2026-10-30. Source audit finds existing thread-local Workspace reuse and Rc<State> ring pooling in the production kernel. Older kernel_efficiency_v1 and recent WORK-PROFILE-REPORT already cover initial-evaluation caching, U-turn alternatives and reverse-check work; do not repeat those as new candidates. No system sampling profiler is currently available in local WSL. Use a bounded allocation-count diagnostic instead, without interpreting instrumented timing as speed.

Wrap the System allocator in an isolated research driver linked to the unchanged production kernel. Count allocation/zeroed-allocation/reallocation events, requested bytes, deallocations/freed bytes and allocation-size bins only while Sampler::run executes. Reset counters per chain. No backtrace capture, changing allocator policy, sampled numerical approximation or production edits. Realloc requested bytes are gross requests, not live or peak memory. Counts include sampler initialization, warmup, retained storage and telemetry; exclude post-run observable summaries and JSON output. They are not native NUTS cost comparisons or proof of a bottleneck.

Replay the five preserved cold qualification inputs (direct/latent banana, identity/diagonal; severe funnel diagonal), four chains each, with profiling disabled then enabled. Require exact all prior emitted fields except seconds, plus identical target calls and zero counters when disabled. Preserve per-chain counters and resource receipts. Normalize allocations by actual calls and warmup+retained transitions; report byte bins without claiming stack attribution. Selection of any optimization requires evidence from this audit and a later uninstrumented same-compiler benchmark with exact trajectory/work parity and fresh validation.

Build300s/4GiB; each serial sampling worker180s/2GiB/64MiB; local free disk floor1GiB. No paid cloud or package installation. Preserve negative findings and do not promote reduced allocation counts alone as practical usefulness.
