### WP50-BRIDGESTAN-WINDOWS-ROOT-CAUSE-V1 — the Windows heap-corruption fault did not reproduce (0/300); H1-as-stated, H2 and H3 refuted by audit and prior evidence; root cause narrowed but not established
- Ordered time: 2026-10-24 on `wt/windows-native-root-cause`. Preregistration, protocol, harness and orchestrator committed at `c4f3fcbb` before the first evidence child. 300 children ran strictly sequentially 17:36–17:46 local; analysis followed immediately.
- Protocol/config: `STUDIES/bridgestan_windows_root_cause_v1/{PREREGISTRATION.md,protocol.json}`. Four frozen hypotheses: H1 emutls autodiff-stack destructor after `FreeLibrary`; H2 allocator mismatch; H3 owned-worker drop order; H4 `STAN_THREADS`.
  - The harness is a direct-`libloading` BridgeStan child and does not use the owned-worker backend. It drives the real `owalnuts::sampler::Sampler` (4 chains/4 threads, 100+100 draws, 4 replicas).
  - Arms: baseline `sampler_concurrent` (resident replicas, concurrent direct calls) 60; H1 `sampler_concurrent_unload` 60; fix `sampler_owned` (one long-lived owner thread, serialized) 120; H4 `STAN_THREADS` model 30 versus no-threads control 30.
  - Models: sblrc and arK rebuilt from posteriordb `28f8d3d` with BridgeStan 2.9.0 / Stan 2.39.0 / WinLibs GCC 16.1.0.
  - Decision rule: a hypothesis is supported only if the baseline reproduces at least once, the fix arm is clean over at least 2x the baseline count, and the mechanism is shown.
- Seeds: 50500001–50500060, 50500201–50500260, 50500401–50500520, 50500801–50500830, 50500901–50500930. The base was exact-word verified unused. Forbidden seeds 90101–90103 are hard-rejected. Calibration (about 295 children on seeds 40000001–40081040) ran before the freeze and is reported as non-evidence.
- Status: all 300 records present; none rerun.
- Outcome: **0/300 faults, 0 `0xC0000374`, in every arm; the baseline did not reproduce. No hypothesis supported empirically.**
  - Baseline 0/60 bounds the fault rate at 4.9% (one-sided 95%). That is inconsistent with the 9edcbac comparator's 8.9% rate (probability 0.004), so this harness and environment differ materially from the reproducing conditions.
  - H2 refuted by the boundary audit: error strings and the model are allocated and freed by the DLL's own CRT, and Rust frees only its own buffers.
  - H3 refuted by the drop-order audit: single owner-thread destruct before library release, owner always joined, no RNG or aliased handle. The owned arm was 0/120 here (0/540 in the prior study).
  - H1 as stated refuted: the faulting non-threads build has no `STAN_THREADS` thread-local autodiff stack (`nm`), and prior reproductions already had resident DLLs and joined workers.
  - H4: threads 0/30 versus control 0/30.
  - Narrowed (not proven): the non-threads build keeps three kinds of per-thread native state torn down at OS-thread exit through mingw TLS callbacks — a thread-id-keyed global autodiff-stack map, emutls C++ EH globals, and libwinpthread `pthread_key` destructors. This is consistent with the prior `ntdll` `0xC0000374` and `libwinpthread` `0xC0000005` signatures and with why one long-lived owner thread clears the fault.
- Anomaly: the children loaded Git's `libwinpthread-1.dll` (63,875 B) ahead of the WinLibs copy (72,171 B) that matches the toolchain that built the models. The prior studies ran from PowerShell and did not record which copy they loaded. This is the leading untested confound for the non-reproduction.
- Payoff: not measured. The preregistered condition (H1 holds) was not met.
