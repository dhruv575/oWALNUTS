- Conclusion: supported — restart-from-best turns the one-bad-chain start failures that no independent-chain sampler (CmdStan, nutpie, the plain driver) recovers into passing cells, at no cost where it does not fire and no measurable bias, and it is now the `sampler` default under the preregistered rule. Not supported: pooling (fails the rule, stays opt-in); a gain on `hmm_drive_0`'s tail ESS (the merged chain is slow); anything on failures that are not one bad chain (funnel R-hat, centered eight schools). Caveat carried into the docs: a `LogDensity` rescue blinds R-hat to the mode that chain had found — the telemetry records it and multimodal users must read it — and the density rule also fires on merely late chains at the first boundary.
- Next decision: (1) a fresh-seed validation of the new default on the full 17-model set against CmdStan and nutpie (the WP32 protocol) so the release figure includes it; (2) the density rule's first-boundary false positives (kidiq, sblrc, earnings) argue for scoring from the second window or requiring the outlier to be an outlier on two consecutive boundaries — a preregistered variant; (3) the slow post-merge `hmm_drive_0` chain suggests re-seeding from the source's *latest* position with its cached evaluation instead of a random window position; (4) candidate C (start retry) is still on record and unmeasured.
