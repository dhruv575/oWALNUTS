# Stored-draw return-tail operational envelope (draft)

This is arithmetic on sealed E64 evidence, with no acquisition or sampler calls. Parent owns AWS lifecycle; this envelope never shuts down the host. Numerical methods and endpoints belong to the separately reviewed scientific protocol. Parent approved a tail-only P5/P95 root wrapper, requiring literal equivalence with the inherited P5/P50/P95 implementation before market arithmetic.

The fixed inputs are 4,368 float64 candidate arrays of shape (4,400,4), totaling 224,200,704 bytes, and 24 float64 reference arrays of shape (4,4000,4), totaling 12,291,072 bytes. Columns are mu, log_sigma, beta, h_last. These files already exist in the sealed remote E64 lane. They are read-only and need not be duplicated into outputs.

Twelve persistent workers occupy cores 0 through 11, with BLAS/OpenMP threads fixed to one. Candidate origins use canonical month-major, increasing-tick ordering and global index modulo 12: exactly 364 origins per worker. After every candidate process has drained, twelve reference workers process two fixed references each. Three monthly reports follow. The fixed operational denominator is 27 jobs, independently of scientific availability. All planned origin slots remain in terminal accounting after timeout or failure.

Proposed caps, to be frozen after literal full-size readiness, are 3,600 seconds internal and 3,720 seconds external; candidate phase 2,700 seconds, reference phase 600 seconds, and report phase 120 seconds. Aggregate RSS is capped at 8 GiB, worker RSS at 1 GiB, and new output at 1 GiB. The sampled output cap is checked every two seconds and again after drainage; it is not a hard filesystem quota. Existing process ownership checks and RSS/deadline checks remain frequent. Every launched group is terminated/drained on completion or failure; an unsafe drainage/resource result blocks later phases.

Whole-job timing includes imports, JIT, input verification and persistence. Quantile arithmetic timing is reported separately and is not full inference or quoting latency. No new timing estimate is treated as measured until the fixed literal readiness completes. Twelve-way parallelism gives 364 candidate tasks per worker; readiness must establish conservative capacity within the 2,700-second phase, including startup and evidence work. Reference arrays have ten times the draws, so they receive their own phase and full-size readiness.

An append-only utilization log records timestamp, phase, owned process identities, CPU-time deltas, RSS and affinity every five seconds. It contains no market values. Its purpose is to distinguish useful CPU work from import/I/O/idle time and support scheduling the next reviewed experiment. No additional work is launched solely to fill idle cores. The outer monitor owns the aggregate 1 GiB cap across all output files. Nested worker byte scans cover only their small monitor/log directories; they do not separately cap scientific row files written elsewhere in the shared batch root.

Input files are parsed from the same bytes whose hashes are checked. Source/runtime bindings and every consumed input hash are verified before and after execution. Origin rows are immutable; partial progress never replaces successful evidence. Numerical failures are recorded as unavailable and do not adapt orders, retries or probabilities. Hard worker failures leave its remaining predetermined slots unattempted. Final accounting distinguishes integrity, process execution and numerical availability.
