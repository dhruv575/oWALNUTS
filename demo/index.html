An Optimized Rust MCMC Sampler

oWALNUTS is an independent implementation of the No-U-Turn sampler variant WALNUTS (Bou-Rabee, Carpenter, Kleppe & Marsden). The Rust implementation matches the paper's implementation with several optimizations and improvements, reproduces their result where NumPyro NUTS fails, and is able to sample 1,000-step latent paths that prior metrics cannot.

Neal's Funnel

Neal's Funnel is considered a hard geometry (the statistics equivalent of trying to run gradient descent with a learning rate that is always too large or too small) that WALNUTS' unique ability to build each orbit with a macro step h — and refine it wherever the orbit needs it — allows it to properly sample.

A metric that makes T = 1,000 routine

Polyscope's forecasting models carry latent random-walk paths a thousand steps long. To study them without guesswork we built a fixture whose posterior is exactly Gaussian with a tridiagonal precision — a local-level model with fixed globals — so every sampler's error to the truth is known, not estimated. Four fixed metrics, same kernel, same seeds: the depth histograms below are the whole story. A prior-based path metric (the kind an earlier Polyscope sampler used) hits the depth cap on 92% of transitions and collapses the step to 0.003; the posterior-precision tridiagonal metric — a banded Cholesky the facade already represents — mixes at depth 4 with roughly a thousand times the effective samples per gradient.

Why the earlier T = 1,000 line failed

nutpie-class speed from PyMC, twice CmdStan in Rust

A better kernel is worth little behind a slow transport. oWALNUTS exposes a GIL-free C-ABI target, so a PyMC model compiled with numba is called at 1.25 µs per gradient and four chains run in parallel. On Eight Schools that puts it ahead of nutpie — the fastest Rust NUTS for PyMC — at equal per-gradient efficiency.

Crypto volatility: the ordinary test

Stochastic-volatility posteriors over the full daily history of the five largest cryptocurrencies — every latent volatility state sampled jointly with the globals, no marginalization. This is not a geometry where WALNUTS has much to exploit: the bottleneck is a correlation ≈ −0.9 ridge between two global parameters, and every sampler tested sits on it. It is here because a sampler you would use has to pass the ordinary test too, and because the comparison is shown in full: nutpie is the fastest wall clock on four of five assets, NumPyro's windowed adaptation passes the primary gate at budget where our one-shot metric needs a labelled 2× compute tier, and every cell — pass or fail — is on the page.

Every cell: 4 chains × 1,000 warmup + 3,000 retained against preregistered gates — primary = rank R-hat ≤ 1.01 and bulk/tail ESS ≥ 400 on μ, hT, mean(h), zero divergences, depth caps ≤ 1%; globals = R-hat ≤ 1.05 and bulk ESS ≥ 100 on the (φ, σ) ridge pair, preregistered as a weaker gate before any evidence because that ridge bottlenecks every tested sampler. Identical gates for every backend. oWALNUTS rows use three fresh seeds (98001–98003, plus partner seeds 98011–98013); nutpie/NumPyro reference rows are single-seed (97001), frozen from the v1 study. “8 chains pooled” rows are a preregistered, labelled 2× compute extension. “fallback B” rows rerun cells whose PyMC-bridge chains stuck under the frozen metric with the rebuild-enabled configuration, as preregistered. oWALNUTS walls are quiet-machine re-measurements of the identical runs (draws bit-identical; contended walls kept in summary.json); PyMC-bridge rows ran at 4 threads through the single-thread transport and carry a ~3× penalty the thread_safe=True path has since removed but not yet re-measured.

What did not pass, and what it costs At the standard budget oWALNUTS misses the primary ESS gate on every BTC seed (T ≈ 3,150) and on one seed each of ETH and BNB; SOL passes primary but not the globals ridge on five of six seeds. Passing everything required the 8-chain pooled tier — twice the compute — where BTC, ETH, XRP and SOL pass both gates on all three seeds and BNB has one residual globals miss (R-hat 1.06). The efficient configuration that closes the gates (Appendix C adaptation, Γ = 0.95) takes finer micro steps, so its wall is ~1.7× the earlier configuration at roughly the same ESS per second; contention explained only 10–30% of the earlier walls. Three PyMC-bridge seeds stalled from bad starts and are shown as they ran. The named next step is a pooled rank-2 arrowhead metric (~1.4× per call in pilots) generalized beyond Polyscope's parameter layout.

Reproduce

The orbit at the top of this page, and the funnel result, in one command from the repository:

git clone https://github.com/dhruv575/oWALNUTS && cd oWALNUTS
cargo run --release --example funnel_orbit_trace      # writes demo/data/funnel-orbit.json
cargo run --release --example funnel_paper_adaptation # P(ω<−5) vs exact, with warmup

From Python, against a PyMC model, GIL-free:

pip install maturin numba pymc arviz
cd integrations/python && maturin develop --release
import owalnuts
target, dim, q0, names, unravel = owalnuts.from_pymc(model, gil_free=True)
result = owalnuts.sample(target, dim, init=q0, chains=4, warmup=1000, draws=1000, threads=4)
idata = result.to_inferencedata(names)
